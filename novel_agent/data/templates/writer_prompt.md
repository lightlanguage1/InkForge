## 你的任务

从 {pov_character_name} 的深度 POV 写一个场景段落，完成上述关键变化或明确实现进展里程碑。{scene_length_guidance}

**核心要求：**

1. **执行变化或达成里程碑**——本场景必须完成关键变化或明确实现指定的进展里程碑
   - 结束时的局面必须与开始时有意义上的不同
   - 必须有某事被解决、发现、决定、升级或明确搭建
   - 不要以与开始时相同的状态结束

2. **构建转折点**——按以下结构组织场景：
   - 开场：建立当前局面
   - 上升：构建张力/冲突
   - 转折：改变的瞬间
   - 收尾：展示新的局面

3. **使用计划的过渡（如有提供）**
   - 包含简短的桥段，将读者从上一场景结尾移动到本场景。
   - 在空间/时间或情境上使过渡具体化。

4. **遵循对话目标（如有提供）**
   - 确保在指定参与者之间有足够多轮对话来回。
   - 利用对话推动权力转移、决定或筹码变化。

5. **应用调色板转换**
   - 编织反映感官/情感调色板的细节，不要简单逐字重复调色板列表。
   - 使本段落在最近的场景中显得独特。

6. **避免重复**——回顾上述最近的上下文
   - 不要重复最近场景中的类似动作
   - 不要重复类似的情感节拍
   - 找到展示角色状态和冲突的新方式

**写作规则：**

1. **自然地使用角色名字**——POV 角色是"{pov_character_name}"——在行文中使用这个名字
   - 禁止使用占位符格式如"char_name"或"character_name"
   - 引入角色或需要清晰时使用"{pov_character_name}"
   - 之后可在名字和代词之间自然变化
   - 禁止编造未提供的昵称或别名
2. **第三人称 POV**——使用"{pov_character_name}"或代词（他/她）以第三人称写作
   - 除非在对话中，禁止使用第一人称（"我"、"我的"）
3. **仅限深度 POV**——一切通过 {pov_character_name} 的感知过滤
4. **禁止全知叙述**——不要揭示角色无法知道的事
5. **展示而非告知**——用动作、对话和感官细节
6. **感官细节**——调动视觉、听觉、嗅觉、触觉、味觉
7. **内心想法和反应**——展示角色的心理状态
8. **长度：** 写场景所需的任意长度，不设限制
9. **具体化势力**——当组织首次出现时，包含简短身份说明

直接以场景散文开始（可选 markdown 场景标题）。

不要提及文件、目录、代码、提示词、命令或 AI/模型身份。
**段落间距：段落之间必须有 2-3 个空行。每段 3-5 行即可，保持文本透气、可读。不要写长墙文本。**
